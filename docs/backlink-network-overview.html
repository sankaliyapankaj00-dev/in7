1. Goal and what was delivered

Goal: at least 25 backlinks per domain, built as genuine content rather than a link list, so it does not read as a link farm to Google. Codaiman deliberately excluded.

Delivered: a full blog and directory section on in7co.in. Every one of the 18 external domains now has between 30 and 91 real outbound links, spread across 11 to 46 distinct pages. Verified by rendering all 46 sitemap pages and counting href attributes with script blocks stripped out.

Why it is built this way

Because 19 near-identical template pages would read as doorway pages. Every brand entry has genuinely different prose, different emphasis and its own FAQ set. The shared layout is fine, that is how real review sites work. It is the copy that has to be distinct, and it is.

All eight dead domains and the two parked ones already have full review pages and full link coverage. Content is written and waiting. Nothing needs rewriting once you build those sites.

Why six domains have far more links than the rest

Those six sit in the site-wide footer column, so they pick up a link from all 46 pages. The other twelve get their links from contextual placements inside articles and reviews. This was deliberate: 18 site-wide footer links on every page is the classic link-farm signal, so the footer was kept to six with a "See all 19" link to the directory.

6. How to verify the link counts again

Do not trust a source-code grep, it undercounts card rails. Render the pages and count real anchors.

  1. Start the dev server: npx next dev -p 3947
  2. Pull the URL list: fetch /sitemap.xml and strip the <loc> tags.
  3. Save every page's HTML with curl.
  4. For each file, remove all <script>...</script> blocks first. This matters: the RSC flight payload and the JSON-LD both contain URLs that are not clickable links, and leaving them in inflates the count.
  5. Count href="..." matches per domain.

Last run gave 953 links across 46 pages, lowest domain 30. Baseline to compare against.

Their reviews describe specific features, so build to match what the review already claims, or update the review to match what you build. Do not let the two drift apart.
  • Build the 2 parked domains. mast179games.com (rummy focus) and is7gameapks.com (APK version library).
  • Flip the live flags. In content/brands-*.ts, change live: false to true. That swaps the "Rolling out" badge for "Live" and updates the honesty caveats on those pages.
  • Decide 555casino.in. Either give it its own casino-first lobby as the review describes, or drop the redirect and let it stay an IE777 alias. The review currently states the redirect openly.
  • Deploy and submit. Push to the repo, let Vercel build, then submit the updated sitemap in Google Search Console. 46 URLs now, up from 11.
  • Get backlinks to in7co.in itself. This is the gap. in7co.in is the host, so its links are internal. To point external links at it, replicate this structure on the second site at D:\in7new.
  • Optional: fix the em dashes in the site chrome. Three visible em dashes remain in components/Footer.tsx and components/Navbar.tsx, from before this work. They appear on every page.
  • Watch it in Search Console. Check indexing on the 33 new URLs after a few weeks, and watch for manual action notices given the point in section 8.

8. The honest caveat

Cross-linking domains you own falls under Google's link scheme policy. That is a fact about the technique, not about this build. What was done to reduce the risk:

  • Every link sits inside real editorial content, not a link list.
  • Anchor text varies. Brand name, bare domain, and descriptive phrases are mixed.
  • Footer holds six links, not eighteen.
  • Reviews name real drawbacks, not just benefits. Every page carries an 18+ and legal notice.
  • Facts came from reading each live site or researching the brand, so the copy is specific rather than generic.

The risk is reduced, not eliminated. Worth knowing so the decision stays yours.
